# 模拟器复查：仍有四处常规战斗问题

日期：2026-09-20；基线：`99fb464`。

**结论：上次反馈的主要修复已经落地，但现在还不能说“模拟结果没问题，可以放心用了”。** 本次只看模拟器正常战斗，确认了下面四处实际问题；不涉及搜索算法、非法输入或跨平台发布。

## 已有进展与验证

上次的资源大小写、首回合挂载被动、拼点胜者 Attack End、选择上方卡、Protection 字段和一回合状态过期，都已有对应修复和测试；之后还补了不可破坏硬币相关处理。

本次执行 `cargo test --workspace`，**99 项测试全部通过**（14 单元 + 10 工程 + 75 机制）。另外在项目外建立小型 Rust 探针，直接调用当前核心代码，隔离验证以下现象。没有修改项目业务代码，也没有运行搜索算法。

## 1. 沉沦次数耗尽后仍会一直触发

**位置**：`sim/crates/lcb-core/src/state.rs:105` 的 `add_count`；`sim/crates/lcb-core/src/battle.rs:3283` 的 `apply_sinking`。

给非理智敌人 10 强度、1 次数的沉沦，连续触发三次受击沉沦处理，实际得到：

```text
第 1 次：扣血 10，剩余强度 10、次数 0
第 2 次：扣血 10，剩余强度 10、次数 0
第 3 次：扣血 10，剩余强度 10、次数 0
```

原因是次数归零没有清除仍有强度的状态，而触发时只判断强度。项目已缓存的日文战斗说明明确写着：这类同时具有强度和次数的状态，其中任一值变为 0 就会消失（`data/_raw/pages/ja_wiki_battle_system_details.txt:391`）。

**影响**：固定队伍大量使用沉沦，对罗生蝶的后续伤害会被持续高估。同样的次数递减／强度读取方式还出现在流血、烧伤等路径，需要一并核对。

**建议**：先修正常状态消耗到零的清除规则，再加“10 强度、1 次数只触发一次”的用例。按状态类型处理，不要对 Butterfly 的特殊双数值结构一律套用。

## 2. 拼点等级加成比较错了属性

**位置**：`sim/crates/lcb-core/src/battle.rs:2340` 的 `match_power`。

普通攻击互相拼点时，应比较双方攻击技能的攻击等级。当前代码计算自己技能攻击等级后，却读取对手的 `defense_level()`，也没有拿到对手当前技能的攻击等级修正。这与项目自己的 `docs/MECHANICS.md` 第 6 条不一致。

用同一个技能、固定反面硬币并排除状态加成，探针得到：

| 仅改变对手的一项属性 | 己方拼点值 |
| --- | ---: |
| 双方等级相同 | 3 |
| 对手防御等级降低 12 | 7，错误地增加了 4 |
| 对手攻击等级降低 12 | 3，反而没有得到应有的加成 |

**影响**：这是普通拼点都会经过的路径，会改变胜负、剩余硬币以及后续伤害，不需要特殊输入才能遇到。

**建议**：拼点时同时传入双方本次技能，使用各自实际攻击等级及技能修正。补一个测试，确认改变防御等级不影响普通攻击之间的拼点，改变攻击等级会产生对应加成。

## 3. “下回合束缚／加速”在速度计算之后才生效

**位置**：`sim/crates/lcb-core/src/battle.rs` 的 `begin_turn`：先读取 Haste/Bind 计算速度，后处理 `pending_next_turn`。

用格里高尔真实技能 `1121401` 的 `[On Use] Gain 1 [Bind] next turn` 做对照，把速度范围固定为 5：

```text
没有该束缚队列：下一回合速度 5
有该束缚队列：下一回合速度仍为 5，但身上已显示 1 Count Bind
```

本应降到 4。现在状态到达时本回合速度已经计算完成，回合末又会过期，因此这次“下回合束缚”错过了影响速度的时机。通过相同队列施加的 Haste 也存在同类顺序问题。

**建议**：先应用下一回合状态，再计算当回合速度。回归测试直接使用这个真实技能，比较有无队列的速度即可。

## 4. 防御技能实际发动后，卡槽没有正常轮换

**位置**：`sim/crates/lcb-core/src/battle.rs` 的 `submit`、`resolve_combat` 防御分支和 `rotate_used_slots`。

选择防御会把 current 改为防御技能，但 resolve_combat 在挂载防御后就将该动作从 pending 中移除，没有把这个槽加入后续轮换用的 executed。

**实际复现**：格里高尔选择 `1121404`，本回合日志确认 Guard 已发动。进入下一回合，current 仍是 `1121404`，next/preview 没有移动，converted 仍为 true。防御卡留在了正常牌面中。

**影响**：普通防御操作会破坏牌组轮换。上次修复了“选择上方攻击卡”，这个防御替换分支仍然遗漏。

**建议**：按防御实际使用规则记录槽位消耗，并保留被替换的原始卡信息，结算时正确消耗和补牌。测试需确认防御确实发动，再检查下一回合牌面；不能只测试护盾是否出现。
